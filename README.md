# Смена 20:00 — проверка штрафов ГИБДД

Веб-приложение для автопарка: список машин, ручная проверка штрафов, журнал постановлений.

Проверка запускается **только по запросу**: кнопка «Проверить сейчас» для всего парка или «Проверить штрафы» у одной машины. Автоматического вечернего запуска нет.

## Что умеет

- хранит список автомобилей (госномер + СТС) и даёт править автопарк в панели: добавить, изменить, удалить машину;
- проверяет штрафы по кнопке, без ночного автозапуска;
- показывает неоплаченные постановления, сумму и срок скидки 25 % (30 дней, ст. 32.2 КоАП РФ);
- умеет прислать сводку в Telegram или на webhook;
- не хранит пароли «Госуслуг» и не показывает посторонние персональные данные.

Официального публичного API у ГИБДД нет: сайт требует капчу, ГИС ГМП — договор. Подключён **API Assist** (`fines_api`): живые неоплаченные постановления по номеру СТС, бесплатно **200 запросов в месяц**.

| `FINES_PROVIDER` | Что делает |
| --- | --- |
| `assist` | **API Assist**, [бесплатно 200 запросов/мес](https://api-assist.com/api/fines) — включён на Amvera |
| `demo` | Учебные постановления, чтобы сразу увидеть панель |
| `cloud` | [API-CLOUD](https://api-cloud.ru/gibdd), ключ по заявке |
| `http` | Ваш API: `FINES_API_URL?plate=&sts=` |

Ключ Assist задаётся переменной окружения `ASSIST_API_KEY` (на Amvera — секрет, в репозиторий не кладётся). Запрос:

`GET https://service.api-assist.com/parser/fines_api/fines?key=…&sts=…`

200 бесплатных запросов хватает примерно на 6 полных проверок 30 машин. Поэтому в панели можно проверить **одну машину** («Проверить штрафы» в карточке). Полная вечерняя проверка 30 машин каждый день — это уже около 900 запросов в месяц, нужен платный лимит.

## Платный API

Для ежедневной смены из 30 машин удобнее **API-CLOUD**: ключ выдают юрлицу или ИП, считают успешные запросы, есть закрывающие документы.

### 1. API-CLOUD (рекомендуется для автопарка)

Документация: [api-cloud.ru/gibdd](https://api-cloud.ru/gibdd)  
Тарифы: [api-cloud.ru/tarif](https://api-cloud.ru/tarif) (не оферта, цены меняются)

Ориентир на сентябрь 2026:

- успешный запрос к ГИБДД оплачивается отдельно (в примере документации списание **0,8 ₽**);
- если за месяц меньше 2000 запросов — ещё **700 ₽** минимального платежа;
- 30 машин × 30 вечеров ≈ 900 запросов: укладываетесь в минимальный платёж + стоимость запросов.

Как подключить:

1. Подготовьте реквизиты юрлица или ИП и название ЭДО (работают только через ЭДО).
2. Напишите на [support@api-cloud.ru](mailto:support@api-cloud.ru):
   - какие методы нужны: `type=fines` (штрафы ГИБДД);
   - объём: около 900 запросов в месяц;
   - цель: ежедневный мониторинг своего автопарка;
   - форма (ООО / ИП) и реквизиты для договора.
3. Дождитесь регистрационного кода (обычно до 7 рабочих дней). Анонимные почты не принимают.
4. В кабинете скопируйте персональный ключ (32 символа).
5. Пропишите в `.env` и перезапустите приложение:

```bash
FINES_PROVIDER=cloud
CLOUD_API_TOKEN=ваш_токен_из_кабинета
```

Приложение само вызывает  
`https://api-cloud.ru/api/gibdd.php?type=fines&regNumber=…&stsNumber=…&token=…`

### 2. API Assist, платный лимит

Тот же API, что и бесплатные 200 запросов: [api-assist.com/api/fines](https://api-assist.com/api/fines)

1. Напишите на [support@api-assist.com](mailto:support@api-assist.com): нужен платный лимит **от 900 запросов/мес** на штрафы по СТС.
2. Получите ключ и условия (цену публично не публикуют).
3. Пропишите:

```bash
FINES_PROVIDER=assist
ASSIST_API_KEY=ваш_ключ
```

Бесплатного ключа на ежедневные 30 машин не хватит: 30 × 30 = 900 > 200.

### 3. Свой договорной API (ГИС ГМП, банк, внутренний шлюз)

Если у компании уже есть легальный канал:

```bash
FINES_PROVIDER=http
FINES_API_URL=https://example.company.ru/fines
FINES_API_TOKEN=необязательный_bearer
```

Ожидается `GET {url}?plate=&sts=` и ответ `{ "fines": [ … ] }` или массив постановлений.

Не подключайте «серые» парсеры сайта гибдд.рф: там капча, а массовый обход — это не ваш автопарк.

## Запуск

Нужен Node.js 20+.

```bash
cp config/vehicles.example.json config/vehicles.json
cp .env.example .env
npm start
```

Откройте [http://localhost:3000](http://localhost:3000).

В примере уже 30 машин. В панели нажмите **«Добавить машину»** или **«Редактировать автопарк»**, чтобы поменять госномера и СТС. Список также лежит в `config/vehicles.json`.

При изменении госномера идентификатор записи сохраняется, поэтому журнал постановлений не теряется.

Разовая проверка без браузера:

```bash
npm run check
```

## Переменные окружения

См. `.env.example`. Главные:

- `SCHEDULE_CHECK=false` — автозапуск по расписанию выключен, проверка только вручную;
- `TIMEZONE=Europe/Moscow`;
- `FINES_PROVIDER=cloud` — платный API-CLOUD для ежедневных 30 машин;
- `CLOUD_API_TOKEN` — токен из кабинета API-CLOUD;
- `FINES_PROVIDER=assist` и `ASSIST_API_KEY` — Assist (200 бесплатно или платный лимит);
- `FINES_API_URL` / `FINES_API_TOKEN` — свой договорной HTTP API;
- `TELEGRAM_BOT_TOKEN` и `TELEGRAM_CHAT_ID` — вечерняя сводка;
- `WEBHOOK_URL` — POST JSON на ваш URL;
- `API_TOKEN` — если задан, все `/api/*` требуют `Authorization: Bearer …`.

## Деплой на Amvera Cloud

В корне лежит `amvera.yml` (Node 20, `npm start`, порт 80, диск `/data`).

1. Создайте приложение в [cloud.amvera.ru](https://cloud.amvera.ru).
2. Привяжите репозиторий и отправьте код:

```bash
git remote add amvera https://git.amvera.ru/<логин>/<имя-проекта>
git push amvera HEAD:master
```

Логин и пароль — от кабинета Amvera. После сборки панель откроется по адресу вида `https://<проект>-<логин>.amvera.io`.
